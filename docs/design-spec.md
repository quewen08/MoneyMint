# 家庭云记账应用 · 设计规格文档（Design Spec）

> 版本：v0.1（P0 设计基线）
> 状态：**供生成设计稿**
> 配套：可交互低保真原型 `docs/prototype/index.html`
> 后端现状：功能已落地（账户 CRUD、借贷平衡校验的「记一笔」、余额、流水、Beancount 导出、离线 push/pull 同步）。本文档是前端/设计侧的唯一事实来源。

---

## 1. 产品概述

### 1.1 一句话定位
类 Beancount 的**复式记账**家庭云记账应用，运行在 NAS 个人云，家庭成员通过网页（Flutter Web / PWA）多端共享同一账本，支持离线记账与联网自动同步。

### 1.2 目标用户
- 家庭财务管理者（老板本人即首位用户，也是内测用户）。
- 需要精确、可审计、可导出 `.beancount`（能被 `bean-check` 校验）记账的进阶用户。

### 1.3 核心差异点（务必在设计上突出）
| 差异 | 设计含义 |
|---|---|
| **复式记账**（每笔交易至少两条借贷分录且必须平衡） | 「记一笔」不是单个金额表单，而是**分录编辑器**，需实时显示借贷是否平衡。 |
| **单一共享账本**（家庭） | 首页/资产汇总以「家庭」视角呈现；P0 暂不做多账本切换 UI，但数据预留 `ledgers`。 |
| **离线优先 + 自动同步** | 全局需有**同步状态指示器**（在线/离线/待同步）；断网也能完整记账。 |
| **可导出 Beancount** | 设置页需有「导出 .beancount」入口；导出的文件可被 `bean-check` 校验通过。 |

### 1.4 非目标（P0 不做，设计上不预留入口或仅做占位）
- 自动导入 OFX/CSV（下期）。
- 多币种 cost 注解换算（P0 仅单币种记账）。
- 登录/鉴权 UI（**已实现**：注册/登录/退出 + Bearer token 会话 + 账本成员鉴权，见 §2.6；设置页仍预留「成员管理」占位）。

## 2. 设计目标与原则

1. **准确优先于花哨**：复式记账的借贷平衡性是生命线，UI 必须让「不平衡」一眼可见、无法误提交。
2. **离线无感**：任何页面断网都应可用；同步是后台行为，不打断记账流。
3. **移动优先**：主场景是手机网页/PWA，桌面网页为响应式适配（不低于 390×844 设计基准）。
4. **克制的信息密度**：家庭账本不需要专业会计的全部维度，首屏只给「净资产 + 账户余额 + 最近几笔」。

## 2.6 账号认证与权限模型（已实现后端）

| 维度 | 方案 |
|---|---|
| 注册 | `POST /api/auth/register`：用户名 + 密码（≥6 位），自动加入默认账本（角色 editor） |
| 登录 | `POST /api/auth/login`：用户名 + 密码，bcrypt 校验，签发随机会话 token |
| 会话 | token 存 `sessions` 表（有效期 30 天），请求头 `Authorization: Bearer <token>` |
| 退出 | `POST /api/auth/logout`：删除该 token，旧 token 立即失效（安全退出） |
| 鉴权 | 统一中间件：除 `/api/health` 与 `/api/auth/*` 外，所有端点需有效 token，否则 `401` |
| 数据隔离 | 家庭账本为**共享账本**：隔离边界是「未登录不可见 / 账本成员可见共享数据」；非成员返回 `403` |
| 当前 UI | 前端首屏为登录/注册页（未登录拦截），AppBar 提供「退出登录」 |

> 设计含义：登录页是产品入口（见原型 login 屏）；所有业务页无需感知鉴权细节，
> 只需在请求头带 token。设置页「退出登录」应置于显眼位置。

## 4. 页面清单与线框说明

> 每个页面在原型 `docs/prototype/index.html` 中可点击预览。下表为设计师的逐页说明。

### 4.1 首页 / 仪表盘（dashboard）
- **顶部**：账本名「家庭账本」+ 同步图标（绿点=已同步 / 黄圈=待同步 / 灰=离线）。
- **主卡**：净资产（所有资产账户余额之和，P0 单币种直接求和）。大字号。
- **账户余额区**：按 资产 / 负债 / 权益 三组的折叠列表，每组显示组内合计与小字明细。
- **最近交易**：最近 3~5 笔，显示日期、摘要、涉及账户、净额。点击进入交易详情。
- **FAB**：右下角悬浮「＋ 记一笔」，主操作入口。
- **离线条**：断网时顶部出现「离线模式 · 数据保存在本机」提示条。

### 4.2 账户（accounts）
- 顶部 Tab「账户」。
- 分组列表：资产（Cash/Card/Bank…）、负债（信用卡/贷款…）、权益（Equity/Opening…）、收入、支出。
- 每行：账户名、类型标签、余额（币种 + 金额）。
- 右上「＋」新建账户 → 跳 4.2.1。
- 点击账户行 → 账户详情（余额、关联交易数；P0 详情可简，点击进流水按该账户筛选）。

### 4.2.1 新建 / 编辑账户（account-edit）
- 字段：账户名（必填）、类型（下拉：资产/负债/权益/收入/支出，必填）、开户日期（默认今天）、币种限制（可选，绑定该账户只能记该币种）。
- 校验：名称 + 类型必填；重名提示（后端已做唯一约束）。
- 提交后回到账户列表，新账户出现在对应分组。

### 4.3 记一笔（record）★核心页
复式记账编辑器，是产品设计重点。
- **头部**：返回、标题「记一笔」、保存按钮（**未平衡时禁用**）。
- **日期**：默认今天，可改。
- **摘要/描述**：单行文本（对应 Beancount narration）。
- **分录列表（postings）**：每行 = 账户（下拉，可搜索）+ 金额（有符号输入框，正=借/增加，负=贷/减少，按账户类型语义由系统解释，但用户视角是「账户 + 金额」）。
  - 至少 2 行（后端校验 ≥2 条分录）。
  - 行末可删除（保留 ≥2 行）。
- **＋ 添加分录**：在列表末尾追加一行。
- **平衡指示器**：实时显示「剩余未平金额」（按币种分组的借贷差）。为 0 且 ≥2 行时显示绿色「已平衡 ✓」，保存可用；否则红色「还差 X.XX 未平」。
- **草稿与离线**：断网时保存写入本地（IndexedDB），标记待同步；联网后由同步层自动 push。
- **设计注意**：金额输入框需支持负数输入与千分位显示；账户下拉在手机上应是可搜索选择器（账户可能很多）。

### 4.4 流水（transactions）
- 顶部 Tab「流水」。
- 按日期分组的交易时间线。
- 每行：日期、摘要、涉及账户（如「Cash → Food」）、净额。
- 筛选栏：按账户筛选、按日期区间（P0 可只做账户筛选，日期区间占位）。
- 点击行 → 交易详情。

### 4.4.1 交易详情（txn-detail）
- 显示日期、摘要、flag。
- **完整借贷分录**：逐行显示 账户 / 金额（有符号）。这是复式记账的「证据」，需清晰呈现借贷两侧。
- 只读（P0 不支持编辑/删除；如需更正，设计为「新增一笔调整/冲正交易」，符合 append-only 约束——但 P0 可不暴露，仅后端支持）。

### 4.5 我的 / 设置（settings）
- 同步状态卡：同步图标 +「上次同步：刚刚 / 2 分钟前」+「待同步 N 条」+「立即同步」按钮。点击展开同步日志（罕见冲突记录）。
- 导出 Beancount：按钮 → 调用 `/api/export` 下载 `family.beancount`。
- 成员管理：占位入口（P0 灰显，标注「即将上线」）。
- 主题：浅色 / 深色切换（P0 至少支持系统跟随）。
- 关于：版本号、后端地址（调试用，可折叠）。

## 5. 核心流程

### 5.1 记账主流程（在线）
1. 首页点 FAB → 记一笔。
2. 选日期、填摘要、添加 ≥2 条分录、填金额。
3. 实时平衡指示器变绿 → 点保存。
4. 调 `POST /api/transactions`（后端校验借贷平衡 `∑=0`）→ 成功 → 回到首页，余额更新。
5. 若不平衡 → 后端返回错误，前端在平衡指示器红字提示，禁止提交。

### 5.2 离线记账 → 同步
1. 断网时首页显示离线条。
2. 记一笔 / 新建账户 → 写入本地 IndexedDB，标 `pending`，UI 立即可见（与在线体验一致）。
3. 联网瞬间：① `POST /api/sync/push`（推送本地 pending，按 uuid 幂等）② `GET /api/sync/pull?since=本地水位`（拉回他人变更）③ 应用变更、更新水位、清 pending。
4. 同步状态图标：pending>0 显示黄圈；同步完成转绿点。

### 5.3 导出
设置页点「导出 Beancount」→ 下载 `.beancount` → 可用 `bean-check family.beancount` 校验通过（已验证）。

## 6. 设计规范基线（供设计稿起步）

> 以下为建议基线，老板可按喜好调整；设计稿落地时以最终稿为准。

### 6.1 栅格与尺寸
- 设计基准：移动端 390 × 844（iPhone 逻辑像素）。
- 内容边距：16px；卡片圆角：12~16px；分组间距：12px。
- 底部 Tab 栏高度：56px（含安全区约 84px）；FAB 直径 56px。

### 6.2 色彩（浅色）
| 用途 | 建议色 |
|---|---|
| 主色 / 主操作 | 蓝 `#3B6EF6` |
| 成功 / 已平衡 | 绿 `#2BA471` |
| 警示 / 未平衡 / 离线 | 橙红 `#E8590C` |
| 背景 | 浅灰 `#F5F6F8` |
| 卡片 | 白 `#FFFFFF` |
| 主文本 | 近黑 `#1A1D1F` |
| 次文本 | 灰 `#6B7280` |
| 分隔线 | `#E5E7EB` |

### 6.3 字体
- 系统字体栈（iOS/Android/Web 各自系统字）；中文优先「PingFang SC / 微软雅黑」。
- 字号：净资产大号 32~36pt；标题 17~18pt；正文 15pt；辅助 12~13pt。
- 数字（金额）建议使用等宽数字（tabular-nums）保证对齐。

### 6.4 组件基线
- 按钮：主按钮实心主色、圆角 10px；次按钮描边。
- 输入框：白底、1px 边框、聚焦主色边框。
- 列表行：左标题 + 右值，44px 最小点击高度。
- 同步图标：状态用颜色区分，不做复杂动画（P0）。

## 7. 数据模型与同步协议（简述，供设计理解）

- **账户 accounts**：id、uuid、name、type（资产/负债/权益/收入/支出）、open_date、commodity_restriction。
- **交易 transactions**：id、uuid、date、flag、description（不可变，改账=新增冲正交易）。
- **分录 postings**：transaction_id、account_id、commodity、amount（有符号定点十进制）。
- **余额**：由 postings 实时累加，不存储（前端/后端按账户+币种求和）。
- **同步**：`sync_log`（统一水位 server_seq）+ `sync_checkpoints`（各端水位）。push 按 uuid 幂等，pull 增量 `since=水位`。交易零冲突；配置实体（同名账户/价格）按自然键合并。

> 详细见 `docs/sync-design.md`。设计侧只需知道：界面要有「同步状态」与「待同步数」两个信号，且离线可完整记账。

## 8. 验收标准 / 设计验收点

- [ ] 首页清晰呈现净资产与账户余额分组。
- [ ] 「记一笔」必须展示实时借贷平衡指示器，未平衡时保存按钮禁用。
- [ ] 分录编辑器支持 ≥2 行、增删行、账户搜索选择、负数金额。
- [ ] 全局同步状态图标在 在线/待同步/离线 三态正确切换。
- [ ] 离线时首页/账户/流水/记一笔均可正常使用，并有离线提示。
- [ ] 设置页「导出 Beancount」可下载文件。
- [ ] 响应式：390×844 为主，桌面网页不破版。
- [ ] 深色模式（至少系统跟随）可用。

## 9. 待确认问题（设计前需老板拍板）

1. **净资产口径**：P0 单币种，净资产 = 资产账户余额之和（不含负债扣减展示方式）。是否首页直接显示「资产合计」还是「资产−负债」净值？建议后者（更直观）。
2. **账户类型默认分组**：是否严格用 Beancount 五类（资产/负债/权益/收入/支出）？还是首页只展示资产/负债/权益，收入支出仅在流水体现？建议五类全展示但首页聚焦前三类。
3. **金额输入语义**：用户直接输入「正负金额」还是分「借/贷」两个方向选择？建议直接输入有符号金额（更贴近 Beancount），但需配清晰标签。
4. **深色模式**是否 P0 必须？建议 P0 支持系统跟随即可。
5. **成员/多账本**：P0 是否完全不露入口，还是放灰显占位？建议灰显占位，避免后期改 IA。
