## 二、背景与目标

### 2.1 背景（现状实测，非推测）

对 `data/ledger.db` 实测结果：

| 验证项 | 实测结果 | 结论 |
|---|---|---|
| 单笔交易按币种平衡 | 不平衡 0 笔 | 已实现（`internal/service/balance.go` 用 `big.Rat` 精确求和） |
| 五类账户合计 = 0 | Assets -25 + Expenses +45 + Liabilities -20 = **0** | 恒等式成立 |
| 权益账户 | `Equity:Opening-Balances` 已在种子清单 | 存在，但仅建账时创建 |
| 期初余额入口 | 新建账户弹窗有「期初余额（可选）」 | 存在，但有 5 处语义缺陷 |
| 关闭账户余额校验 | `closeAccount` 直接置 `close_date`，无校验 | **缺失** |

> 代码事实补充（v1.1 复核）：迁移列表已执行到 `011_session_meta`，`010_force_password_change` 与 `011_session_meta` 分别被强制改密、会话元信息占用（`internal/db/migrate.go` 第 16-27 行）；同步实体枚举只有 `account / transaction / commodity / price` 四类，不含 `ledger`（`internal/domain/models.go` 第 32-35 行）。本版据此调整迁移编号与期初日期的读取路径。

**核心问题定性**：账核层面恒等式成立且已被每笔交易的平衡校验所保证；真正的缺口在**表述层与派生层**——五类账户的符号约定没有唯一实现，导致净值算错、负号被静默吞掉、期初余额只能录一半。

### 2.2 目标

| 编号 | 目标 | 成功标准（口径） |
|---|---|---|
| G-01 | 期初余额可正确录入与维护，覆盖资产与负债 | 资产按「持有」、负债按「欠款」录入绝对值，落库符号必正确（资产正、负债负）；编辑账户可见并可修正期初余额；录入成功率 100%（无「填不进去」路径） |
| G-02 | 期初日期统一为账本级单一来源 | 账本内所有期初交易日期 = `ledgers.opening_date`，偏差笔数 0 |
| G-03 | 符号口径全链一致：账本符号 = 界面符号 | 导出与界面显示的符号一致率 100%；刻意构造的负净值/负资产余额能被如实显示 |
| G-04 | 恒等式异常可被发现 | 五类合计 ≠ 0 时 100% 触发告警（导出前、备份前、首页校验卡三处） |
| G-05 | 关闭账户前余额必须为 0 | 有余额账户关闭操作 100% 被拦截，并给出差额 |
| G-06 | 导出的 `.beancount` 持续通过 `bean-check` | `bean-check` 退出码 0，覆盖率 100%（含期初相关全部场景） |

**本期为内部账务正确性需求，不设转化率类业务指标**；核心度量是「导出校验通过率」与「期初/符号类缺陷数」，口径见第十章。

## 三、名词与术语定义

| 术语 | 定义 |
|---|---|
| 五类账户 | `Assets` / `Liabilities` / `Equity` / `Income` / `Expenses`，Beancount 的顶层账户类型 |
| 恒等式 | Σ(Assets) + Σ(Liabilities) + Σ(Equity) + Σ(Income) + Σ(Expenses) = 0（按币种分组）。因负债、权益、收入按负数存储，故为加法关系 |
| 账本符号 | 落库与导出使用的符号：资产、支出为正，负债、权益、收入为负 |
| 展示符号 | 界面呈现的符号。本期规则：**与账本符号完全一致，不做翻转** |
| 期初余额 | 账户在启用时点的既有余额，通过与 `Equity:Opening-Balances` 对冲的期初交易表达 |
| 期初交易 | `description` 含期初语义且 `tags` 含 `opening` 的交易，每账户至多一条有效记录 |
| 账本级期初日期 | `ledgers.opening_date`，账本内所有期初交易的唯一日期来源 |
| 冲正 | append-only 模型下撤销既有交易的方式：新增一笔金额相反的交易，原交易保留 |
| 活跃账户 | 在指定日期处于 `open_date ≤ 日期 ≤ close_date` 区间的账户 |
| 恒等式检查 | 按币种汇总全账 posting，校验合计为 0 的只读检查 |

## 五、方案对比与选型说明

### 5.1 期初余额的表达方式

| 方案 | 思路 | 实现成本 | 开发复杂度 | 用户体验 | 风险 | 上线时间 |
|---|---|---|---|---|---|---|
| **A 权益对冲交易**（推荐） | 期初作为账户属性，生成 `账户 +N / Equity:Opening-Balances -N` 的普通交易 | 低 | 低 | 中（期初会出现在流水） | 低 | 快 |
| B `pad` + `balance` 断言 | 不建交易，导出时靠断言与补平指令 | 中 | 中 | 差（前端无余额锚点） | 高 | 慢 |
| C 期初建账向导 | 首启批量录入全部账户余额 | 中 | 中 | 好（但仅新账本） | 中 | 中 |

**推荐结论：采用 A**，理由：

1. 数据模型已存在（账户、对冲交易、类型校验齐备），改动集中在账户弹窗、一条迁移（012）与账本读取字段，不触碰账核，也不扩展 push/pull 实体枚举
2. 期初作为一笔可追溯的交易，与 append-only 不可变模型天然契合；`pad` 生成的补差交易是运行时虚拟插入，无法落库、无法同步、无法审计
3. B 方案实测不满足可用性底线，详见 5.2

**演进路径**：本期 A（交易式期初）→ 二期视情况追加 N-01（`pad` + `balance` 作为**导出可选增强**，默认关闭）→ 触发条件为"出现外部对账单需批量补差且差额来源可解释"；C（建账向导）触发条件为"新用户首次建账需录入 ≥5 个账户"。

### 5.2 实测否决证据（bean-check 3.2.3，本项目 `.venv` 内实跑）

| 编号 | 实测场景 | 结果 | 对方案的影响 |
|---|---|---|---|
| T-01 | `close` 时账户余额非零（100 CNY 未清零即 close） | 退出码 **0**，无报错 | 「关闭必须为 0」是**业务规则**，校验器不拦，必须自实现（对应 S-07） |
| T-02 | `pad` 与 `balance` 同日 | 报 `Unused Pad entry` + `Balance failed` | `pad` 必须严格早于 `balance`，自动生成极易踩空 |
| T-03 | `pad` 在前一日 + `balance` 在后一日 | 通过，但会**自动插入一条补差 Transaction** | 差额被静默吸收进权益，账面永远"平"，漏记被隐藏 |
| T-04 | 只有 `pad` 无 `balance` | 退出码 0，`pad` 无任何效果 | `pad` 单独存在无意义，必须成对 |
| T-05 | 交易日期早于账户 `open_date` | 报 `Invalid reference to inactive account` | **账户 `open_date` 必须 ≤ 期初日期**，否则导出必失败 |
| T-06 | 账户 `close` 之后仍有交易 | 报 `Invalid reference to inactive account` | 关闭约束有效；但"关闭时余额非零"不被拦截，与 T-01 互为补充 |

> T-05 是本期最容易被忽略的坑：现状 `createAccount` 把 `open_date` 硬编码为 `todayStr()`（`account_dialog.dart` 第 98-131 行），而账本期初日期可能是过去日期。本期由 FR-03 修正新建路径、FR-24 修正存量未关闭账户，否则期初交易必然早于开户日，导出直接报错。

### 5.3 符号展示策略

| 方案 | 做法 | 评价 |
|---|---|---|
| **A 与账本符号一致**（推荐，老板拍板） | 负债显示 `-5,000`、收入显示 `-5,000`；用中文标签补充语义 | 与 Fava 的常见默认表现接近（Fava 侧行为待核实，见 15.5，不构成本决策依据）；实现成本最低，只需去掉格式化层的无条件取绝对值 |
| B 展示时翻转符号 | 负债、收入显示为正数 | 需引入全站归一化层，且与导出对照时需二次换算，易出新错 |

**推荐 A**。同时据此**简化原方案**：上一轮提出的「单一归一化函数 `displayBalance`」在 A 之下不再需要——既然展示符号 = 账本符号，就不存在转换，只需修正格式化层与净值算式两处。此决策变更已记入 5.4 变更说明。

### 5.4 决策变更说明（相对上一轮精简版梳理）

| 编号 | 原方案 | 变更后 | 理由 |
|---|---|---|---|
| CH-01 | 新增 `displayBalance(type, raw)` 归一化函数，全站页面统一调用 | 取消该函数 | 老板选定「展示负数」，与账本符号一致即无转换需求；保留函数属过度设计 |
| CH-02 | `pad` 断言在存量补种时使用 | 本期不做，记 N-01 | 实测 T-02/T-03 表明其生效条件苛刻且会隐藏差额 |
| CH-03 | 期初日期默认取账户 `open_date` | 改为账本级 `ledgers.opening_date` 统一取值 | 老板拍板；同时新增「账户 open_date ≤ 账本 opening_date」硬约束（T-05） |
| CH-04 | 期初输入允许正负，负债填正数仅提示方向确认 | 改为「金额绝对值 + 方向」，方向文案固定为「持有 / 欠款」（Assets 默认持有、Liabilities 默认欠款），内部按账本符号落库 | 旧方案会把负债录成资产且不报错，属正确性缺陷而非提示问题 |
| CH-05 | 同步实体扩展 `ledgers`，push/pull 载荷携带 `opening_date` | 不扩展同步枚举；账本期初日期经既有 `GET /api/ledgers` 读取路径暴露，离线端进入账本时拉取一次并本地缓存 | 同步实体枚举无 `ledger`（`internal/domain/models.go` 第 32-35 行），强行扩展会改动同步协议与幂等语义，成本高于收益 |
| CH-06 | 新增迁移 010 | 迁移号改为 012 | 010_force_password_change、011_session_meta 已占用 |

## 六、用户角色与使用场景

| 角色 | 描述 | 主要场景 |
|---|---|---|
| 账本 owner（老板本人及家庭管理员） | 建账、设期初、维护账户 | 新账本设期初日期 → 录各账户期初余额 → 逐月记账 → 导出核对 |
| 家庭编辑者（editor） | 日常记账 | 查看期初交易标识，理解为何资产余额从某值起算 |
| 只读成员（viewer） | 查看账本 | 查看净值与收支；负净值时能看出是真的为负 |

> 画像说明：以上角色基于项目既有的 `owner / editor / viewer` 权限模型构建，未做用户调研，不涉及人口属性假设。

### 6.1 核心场景（主流程）

1. owner 建账，系统设定账本期初日期（默认建账日，可调，且不得晚于今日）
2. owner 新建「招商银行储蓄卡」，类型 Assets，金额 12500.00、方向「持有」→ 系统生成期初交易，日期取账本期初日期
3. owner 新建「招行信用卡」，类型 Liabilities，金额 3200、方向默认「欠款」→ 系统按账本符号落库 -3200 并生成期初交易
4. 家庭日常记账，资产与负债随交易变化
5. owner 导出 `.beancount` → `bean-check` 通过
6. owner 查看首页净资产 → 数值等于「资产合计 + 负债合计」

### 6.2 异常场景

| 场景 | 期望 |
|---|---|
| 给支出/收入类账户填期初余额 | 输入框禁用并提示「支出与收入类账户不设期初余额」 |
| 期初余额填 0 或留空 | 不生成期初交易，账户期初为 0 |
| 编辑账户时期初余额被改 | 冲正旧期初交易 + 新建，界面提示「已重建期初交易」 |
| 关闭有余额的账户 | 阻断，提示差额并提供转出入口 |
| 五类合计 ≠ 0 | 首页告警条 + 导出结果附带提示，但**不阻断导出** |
| 负债期初录成正数（用户理解偏差） | 方向文案固定为「持有 / 欠款」：金额只收非负值，Assets 默认持有、Liabilities 默认欠款，落库必为负数；改向需二次确认（持有 ↔ 欠款） |
| 离线状态关闭账户 | 关闭按钮置灰并提示「联网后可关闭账户」，不提供离线关闭路径 |
| 离线状态设置期初（期初余额 / 期初日期） | 期初设置入口置灰并提示「联网后可设置期初」；期初交易不进离线队列 |

## 七、功能需求

### 7.1 账本级期初日期

| 编号 | 需求描述 | 业务规则 | 验收标准 |
|---|---|---|---|
| FR-01 | 账本必须具备期初日期字段 | 新增 `ledgers.opening_date TEXT`（`YYYY-MM-DD`，**迁移 012**；010/011 已被强制改密、会话元信息占用）；建账时默认取建账当日；非空 | Given 新建账本，When 建账完成，Then `opening_date` 有值且等于建账当日 |
| FR-02 | 账本期初日期可修改 | 仅 owner 可改且**仅在线可用**（离线入口置灰并提示联网）；新值必须 ≤ **今日**，且 ≤ 账本内最早交易日期（不满足则拒绝并提示最早交易日期或今日上限）；修改成功后触发「重建全部期初交易」二次确认 | Given 账本最早交易为 2026-01-15，When owner 把期初日期改为 2026-02-01，Then 拒绝修改并提示「不得晚于最早交易 2026-01-15」；Given 今日为 2026-11-05，When 选择 2026-12-01，Then 保存按钮置灰并提示「不得晚于今日」；Given 离线，Then 设置入口置灰 |
| FR-03 | 账户开户日不得晚于账本期初日期 | 新建账户时 `open_date` 取 `min(账本期初日期, 今日)`；用户若手工指定，必须 ≤ 账本期初日期；存量未关闭账户由迁移 012 统一修正（FR-24） | Given 账本期初日期为 2026-01-01，When 新建账户，Then 账户 `open_date` = 2026-01-01，导出后 `bean-check` 退出码 0 |

### 7.2 期初余额录入

| 编号 | 需求描述 | 业务规则 | 验收标准 |
|---|---|---|---|
| FR-04 | 新建账户可填期初余额 | 仅 `Assets` / `Liabilities` 可填；`Equity` 与 `Income` / `Expenses` 隐藏或禁用该输入框 | Given 选择类型 Expenses，When 查看账户弹窗，Then 期初余额输入框不可用并给出说明文案 |
| FR-05 | 期初金额按「金额绝对值 + 方向」录入 | **仅在线可用**（离线期初字段置灰并提示联网）；输入框只接收非负金额并保留币种精度（默认 2 位）；方向文案固定为「持有 / 欠款」两个取值（`Assets` 默认持有、`Liabilities` 默认欠款）；落库符号由账本符号决定——持有 = 正、欠款 = 负。不得出现「负债填正数被落成资产」的路径 | Given 类型 Liabilities、方向=欠款、金额 3200，When 保存，Then 落库 -3200 并生成期初交易；Given 类型 Assets、方向=持有、金额 3200，When 保存，Then 落库 +3200；Given 离线，Then 期初字段置灰 |
| FR-06 | 期初交易的对冲规则 | 生成一笔交易：`date = ledgers.opening_date`、`description = "期初余额"`、`tags = ["opening"]`；posting 为「目标账户 +N」与「`Equity:Opening-Balances` -N」（N 为按方向映射后的带符号金额），币种一致；N 为 0 时不生成 | Given 填 12500，When 保存，Then 生成两条 posting 且按币种合计为 0 |
| FR-07 | 期初余额币种确定规则 | 优先级：账户 `commodity_restriction` → 账本 `default_commodity` → `CNY` | Given 账户限定 USD，When 填期初 100，Then 期初交易币种为 USD |
| FR-08 | 权益账户不存在时的兜底 | 若账本缺 `Equity:Opening-Balances`，录入时按 FR-21 规则即时补种后再生成期初交易，不向用户报错 | Given 账本无权益账户，When 录入期初余额，Then 自动补种权益账户并成功生成期初交易 |

### 7.3 期初余额查看与修正

| 编号 | 需求描述 | 业务规则 | 验收标准 |
|---|---|---|---|
| FR-09 | 编辑账户可查看当前期初余额 | 按 `tags` 含 `opening` 且 posting 命中该账户的交易反查；**排除已冲正记录**（冲正状态需持久化支撑，具体字段与判定方式由架构阶段确定） | Given 账户期初为 12500，When 打开编辑账户，Then 期初余额栏预填 12500.00；Given 该账户存在被冲正的旧期初，Then 不预填旧值 |
| FR-10 | 期初余额可修正 | 修改时执行「冲正旧期初交易 + 新建期初交易」；原交易保留并标记为已冲正；冲正与新建在同一事务内，任一失败全部回滚 | Given 期初 12500，When 改为 13000，Then 新增 2 笔交易（冲正 + 新期初），账户余额变动 500 |
| FR-11 | 期初交易幂等且唯一 | 同一账户至多存在一条**有效**期初交易；该唯一性与重复提交去重**需由新增持久化字段支撑**（期初关联字段 / 幂等键 / 冲正标记的组合由架构阶段确定，PRD 不固化字段名）；并发重复提交只成功一次 | Given 连续两次提交相同期初，When 两次请求均到达，Then 只生成一条有效期初交易；Given 绕过前端直接重复写入，When 持久化层校验生效，Then 仍至多一条有效记录 |

### 7.4 符号口径统一

| 编号 | 需求描述 | 业务规则 | 验收标准 |
|---|---|---|---|
| FR-12 | 金额格式化不得吞掉负号 | `formatAmount` 移除无条件 `abs()`；负号如实输出；需要绝对值展示的调用点显式取绝对值 | Given 余额为 -25，When 渲染，Then 显示 `-¥ 25.00` |
| FR-13 | 净值算式修正 | 净资产 = Σ(Assets 余额) + Σ(Liabilities 余额)（负债已为负数，**不得再取反**），按币种分组 | Given 资产 100、负债 -20，When 查看净资产，Then 显示 `¥ 80.00` |
| FR-14 | 净值双算校验 | 同时计算 `ΣAssets + ΣLiabilities` 与 `-(ΣIncome + ΣEquity) - ΣExpenses`，两者必须相等；不相等时输出诊断日志并触发 FR-17 告警 | Given 任一账本，When 刷新首页，Then 两式差值恒为 0 |
| FR-15 | 负净值必须显示负号，且净值文案统一 | 净值卡与资产页均以带符号方式渲染，不得使用绝对值；首页与资产页净值卡文案统一为「净资产（资产 + 负债，负债为负）」，替换现存的「净资产（资产 − 负债）」 | Given 算得净值为 -45，When 查看首页净值卡，Then 显示 `-¥ 45.00` 且文案为「净资产（资产 + 负债，负债为负）」；Given 打开资产页，When 查看净值卡，Then 文案与首页一致 |

### 7.5 恒等式告警

| 编号 | 需求描述 | 业务规则 | 验收标准 |
|---|---|---|---|
| FR-16 | 新增恒等式检查能力 | 后端提供按币种汇总全账 posting 并判断合计是否为 0 的只读检查，返回 `{balanced, diffs:[{commodity, sum}]}` | Given 构造脏数据使某币种合计为 0.01，When 调用检查，Then 返回 `balanced=false` 且 diffs 含该币种与差额 |
| FR-17 | 告警触发点 | 触发于：导出前、备份前、首页手动刷新校验卡；三处均只记录与提示 | Given 账本不平，When 执行导出，Then 导出继续执行，同时在响应中附带「账本不平」提示与差额明细 |
| FR-18 | 告警展示 | 首页展示告警条（含差额币种与金额、跳转导出/校验入口）；允许当次关闭，下次刷新重新出现 | Given 账本不平，When 打开首页，Then 顶部出现告警条；点击关闭后当次隐藏，刷新后重现 |

### 7.6 关闭账户余额校验

| 编号 | 需求描述 | 业务规则 | 验收标准 |
|---|---|---|---|
| FR-19 | 关闭前校验余额为零（仅在线） | 关闭账户**仅在线可用**：离线时按钮置灰并提示「联网后可关闭账户」。在线关闭前按币种校验余额是否为 0；非 0 则拒绝并提示差额；仅 0 时允许置 `close_date` | Given 信用卡余额 -3200，When 在线关闭该账户，Then 拒绝并提示「余额 -3,200.00，请先转出」；Given 离线，When 点击关闭，Then 按钮置灰且不发起请求 |
| FR-20 | 提供余额转出引导（仅在线） | 拒绝后给出「转到其他账户」入口（仅在线可用，离线隐藏并提示联网）；预填金额为该账户全部余额、日期为关闭日；posting 规则：源账户 posting = **-账户当前余额**，对手方 posting = **+该余额**；默认目标：负债账户 → 资产账户（还款语义），资产账户 → 同类资产账户（转账语义），用户可改但不能选同类负债/支出账户 | Given 信用卡 -3200，When 转出到 Bank，Then 生成 `Assets:Bank -3200` / `Liabilities:Card +3200`，原账户余额归零，随后关闭成功；Given 离线，Then 转出入口不可用 |

### 7.7 存量迁移与补种

| 编号 | 需求描述 | 业务规则 | 验收标准 |
|---|---|---|---|
| FR-21 | 权益账户补种 | **迁移 012** 中为缺少 `Equity:Opening-Balances` 的账本插入该账户，`open_date` = 该账本 `opening_date`；幂等，重复执行不重复插入 | Given 老库账本无权益账户，When 执行迁移 012，Then 插入 1 条；再次执行不再新增 |
| FR-22 | 期初日期回填 | **迁移 012** 中存量账本回填 `opening_date = min(最早交易日期, 建账日期, 今日)`；无交易的账本取建账日期 | Given 老账本最早交易 2025-06-01、建账日 2025-08-01，When 迁移，Then `opening_date` = 2025-06-01 |
| FR-23 | 已关闭账户不清洗 | 补种与回填不修改任何已关闭账户的账务与 `open_date`；不合并、不迁移其历史交易 | Given 存在已关闭账户，When 执行迁移 012，Then 该账户记录（含 `open_date`）与其历史交易完全不变 |
| FR-24 | 迁移修正未关闭账户的开户日 | 迁移 012 中，对 `close_date` 为空（未关闭）的账户执行 `open_date = min(open_date, 账本 opening_date)`；已关闭账户保持不变（与 FR-23 一致）；修正前后的值写入迁移日志，保证可追溯、可复算 | Given 老库账户 `open_date=2026-11-05`、账本回填 `opening_date=2025-06-01`，When 执行迁移 012，Then 该账户 `open_date` 调整为 2025-06-01，导出 `bean-check` 退出码 0；Given 已关闭账户，Then `open_date` 不变 |

| 类别 | 要求 |
|---|---|
| 性能 | 恒等式检查在 1 万条 posting 规模下响应 ≤ 300ms（估算；口径为单币种全表聚合）；首页刷新增加的检查耗时 ≤ 100ms（估算） |
| 数据一致性 | 期初交易的冲正与重建必须在单事务内完成；迁移 012 全部语句幂等，重复执行结果一致（`open_date = min(...)` 天然幂等） |

| 数据安全 | 期初余额属账务敏感数据，不上报任何外部服务；同步仅走既有加密通道 |

## 九、业务流程与状态流转

### 9.1 期初余额录入流程

```
新建/编辑账户
  ├─ 离线 ──→ 期初字段置灰，提示「联网后可设置期初」，结束
  ├─ 类型 ∈ {Income, Expenses} ──→ 禁用期初输入，结束
  ├─ 类型 = Equity ─────────────→ 禁用期初输入，结束
  └─ 类型 ∈ {Assets, Liabilities}
       ├─ 方向：持有 / 欠款（Assets 默认持有，Liabilities 默认欠款；改向需二次确认）
       ├─ 金额（绝对值）为空或 0 ──→ 仅创建账户，不生成期初交易
       └─ 金额非 0
            ├─ 映射账本符号：持有 = +金额，欠款 = -金额
            ├─ 已存在有效期初交易（编辑态）──→ 冲正旧交易 ──┐
            └─ 无 ───────────────────────────────────────┤
                                                          ↓
                             查找 Equity:Opening-Balances
                               ├─ 不存在 ──→ 按 FR-21 即时补种
                               └─ 存在 ──→ 生成期初交易（date = opening_date，tags=[opening]）
```

### 9.2 期初交易状态机

| 状态 | 触发事件 | 迁移条件 | 允许操作 |
|---|---|---|---|
| `active`（有效） | 创建期初交易成功 | 生成成功且未被冲正 | 查看、冲正 |
| `reversed`（已冲正） | 用户修正期初余额 | 冲正交易创建成功 | 仅查看（保留审计） |
| `absent`（无期初） | 未填期初 / 期初为 0 / 期初被冲正后重建失败回滚 | — | 可新增 |

> 状态单向：`absent → active → reversed`；`reversed` 不可回到 `active`，需新建一条 `active`。

### 9.3 关闭账户流程

```
请求关闭账户
  ├─ 离线 ──→ 按钮置灰 / 拒绝，提示「联网后可关闭账户」
  ├─ 余额按币种全部为 0 ──→ 置 close_date（今日）──→ 成功
  └─ 存在非 0 币种
       └─ 拒绝关闭，返回差额明细 ──→ 展示「转到其他账户」入口
                                        └─ 转出完成 ──→ 再次发起关闭
```

### 10.1 数据结构变更（迁移 012 + 期初元数据）

> 除期初元数据（新增表或新增字段，由架构阶段决定）外，无其他新增表；新增期初专用端点（账户期初的设置 / 读取 / 冲正，路径与形状由架构阶段确定）。

### 10.2 指标口径定义

## 十二、异常处理清单

| 场景 | 表现 | 处理方式 |
|---|---|---|
| 期初日期晚于最早交易 | 导出报 `Invalid reference to inactive account` | 保存前拦截（FR-02）；导出前预校验，提示具体账户与日期 |
| 账户 open_date 晚于期初日期 | 同上 | 新建账户强制 `open_date ≤ 账本 opening_date`（FR-03）；存量未关闭账户由迁移 012 收敛（FR-24） |
| 权益账户缺失 | 期初无法生成 | 即时补种（FR-08），不阻断用户操作 |
| 权益账户被用户删除/关闭 | 期初无法生成 | 校验权益账户处于活跃态，否则提示「期初余额账户已关闭，请先恢复」 |
| 期初金额格式非法（含字母、多个小数点） | 保存失败 | 输入即校验，指出具体位置与期望格式 |
| 期初金额超出币种精度 | 精度被截断产生差额 | 按币种精度统一舍入，禁止截断；舍入后仍平衡 |
| 冲正过程中断（事务失败） | 可能出现双期初或零期初 | 单事务保证原子性；失败回滚并提示重试 |
| 并发重复提交期初 | 可能生成两条期初 | 幂等处理 + 持久化层的「每账户至多一条有效期初」约束（表与字段设计由架构阶段确定，见 10.1） |
| 关闭后仍需记账 | 导出报 inactive account | 关闭操作给出明确提示；如需继续使用，重新开户生成新账户而非复用 |
| 五类合计 ≠ 0 | 净值与资产页数据不可信 | 告警条提示 + 导出附带提示（不阻断，老板决策） |
| 多币种账本某币种不平 | 单币种差异 | 告警按币种分别列出，不合并展示 |
| 老库账户 `open_date` 晚于回填后的账本期初日期 | 期初交易早于开户日，导出报 inactive account | 迁移 012 对未关闭账户执行 `open_date = min(open_date, opening_date)`（FR-24）；已关闭账户按 FR-23 不动，导出前预校验给出提示 |
| 老库无 `opening_date` 且无任何交易 | 期初日期无处回填 | 取建账日期；建账日期缺失时取今日 |

### 15.3 原型思路

**页面一：账本设置 · 期初日期**

```
所属任务流：设账本基础 → 设期初
布局：
- 顶部：返回 / 账本设置
- 内容区：期初日期行（当前值 + 编辑）→ 说明文案「账本内所有期初余额将记在这一天」
         → 约束提示「不得晚于今日，且不得晚于最早交易 2026-01-15」→ 账户开户日联动说明
- 操作区：保存
交互：
- 正常态：展示当前日期，点击进入日期选择
- 错误态：选到早于约束的日期时，保存按钮置灰并就地提示原因
- 二次确认：保存后弹「将重建 N 笔期初交易」，确认才执行
```

**页面二：账户弹窗 · 期初余额**

```
布局：
- 类型选择（Assets/Liabilities/Equity/Income/Expenses）
- 若类型 ∈ {Equity, Income, Expenses}：期初余额输入框禁用 + 说明文案
- 若类型 ∈ {Assets, Liabilities}：期初表单为「金额（仅非负，后缀显示确定币种）+ 方向（持有 / 欠款）」
  - Assets 默认方向「持有」，Liabilities 默认方向「欠款」
- 编辑态：期初余额预填当前值（按方向反推为绝对值）；下方灰字「修改将重建期初交易」
交互：
- 方向与账户类型默认值不一致时，保存前二次确认「将按<方向>记账，确认？」
- 期初为 0 或空：不生成期初交易，界面不出现「期初」标识
```

**页面三：首页 · 恒等式告警条**

```
布局：
- 位于头部下方，整行警示色
- 文案：「账本不平：CNY 差 0.01」+「查看明细」+ 关闭按钮
交互：
- 点击查看明细：跳转校验卡，按币种列出差额
- 关闭：当次隐藏，刷新后重现
- 无障碍：文案完整描述差额，不只靠颜色
```

**页面四：关闭账户 · 拦截与转出**

```
布局：
- 拦截弹窗：标题「账户余额未结清」→ 差额明细（按币种）→ 说明「关闭后该账户不可再记账」
- 操作：取消 / 转到其他账户
交互：
- 点「转到其他账户」：预填全额（源账户 posting = -当前余额）、日期为关闭日
- 默认目标账户：负债账户默认选资产账户（还款语义），资产账户默认选同类资产账户（转账语义）
- 转出成功：自动回到关闭流程，再次校验为 0 后关闭成功
```
