## 二、前端任务

### F-1 Theme 与共享组件（1 天）

**目标**：改版的设计系统一次性建立，两端（PC/移动）自动继承。

**改动文件**：`app/theme.dart`（重构）、`widgets/common.dart`（新增组件）、新增 `widgets/hero_header.dart`、`widgets/category_icon.dart`

**要点**：
- 色板扩展：渐变蓝 `#1D2B5F→#3B6EF6`（hero 专用）、支出橙 `#F28C28`、成功绿 `#2BA471`、危险红 `#E24B4A`、分类彩色系（8~10 色 50 淡底）
- 新组件：
  - `HeroHeader`：渐变汇总头（标题行/账本 pill/大数字行/竖分隔线），支持右侧 actions
  - `CategoryIcon`：emoji + 彩色淡底圆角块（读 accounts.icon/color，无则按 hash 取色）
  - `UpliftCard`：白卡上浮（负 margin 叠渐变头）
  - `LedgerPill`：账本名 ▾，点击进账本切换
  - `SectionCard`：卡片标题 + more 链接
- **保留隐私遮挡**（`privacy.dart`）：金额隐私开关必须接入所有新金额位，家庭场景防瞟屏是既有功能
- 金额排版统一 `tabular-nums`

**验收**：demo 页能展示全部组件；现有页面在新 theme 下无错位（旧页面允许暂丑，不崩）。

### F-2 导航壳重组（0.5 天）

**目标**：移动端 3 Tab + 中央＋；PC 侧边栏分组落地。

**改动文件**：`app/navigation.dart`、`screens/shell/mobile_shell.dart`、`screens/shell/desktop_shell.dart`、`app/app.dart`（路由表）

**要点**：
- 移动端 Tab：**账单 / 资产 / ＋(FAB) / 报表 / 更多**；FAB 打开记一笔弹层（F-3）
- 流水不再占 Tab：入口 = 账单页右上 📋、账单列表视图、资产页账户详情
- `NavGroup` 分组落地（PC 侧边栏）：概览(仪表盘/报表) · 管理(交易/账户/成员/账本) · 工具(导入导出/币种) · 系统(同步/设置)；底部记账主按钮
- 新增路由：reports（提升为 Tab）、保留 transactions（从入口进）
- 登录/注册/改密为全屏路由（无 Tab 壳）

**验收**：两端导航正确切换；深链路由（PWA 直开某页）不破。

### F-3 记一笔重构（1.5 天，最重）

**目标**：中央＋弹层，支出/收入/转账三 Tab，单录操作 + 复式可见。

**改动文件**：`screens/record/`（重构 record_screen/record_dialog）、新增 `widgets/num_keyboard.dart`、`widgets/category_picker.dart`

**要点**：
- 底部弹层（移动）/ 居中面板（PC），三 Tab 切换
- 金额大屏 + 自定义数字键盘（含 ⌫ / ＋ / － / 再记）
- 分类九宫格：数据源 = `Expenses`（支出）/`Income`（收入）类型账户，读 icon/color
- **资金账户选择器**：描边强调（必选项），记住上次选择
- **分录预览行**：`Expenses:食品饮料:食品 +38.50 ← 招商储蓄 −38.50`（实时随分类/账户/金额刷新）
- **转账面板**：转出 → 转入（虚线占位提示选择）→ 可选手续费；预览两笔 posting；同账本内转账
- **高级模式入口**：展开手动编辑科目路径（三级分类选择）、多笔拆分 posting
- 离线兼容：提交走既有双路径（在线 `account_id` / 离线 push `account_uuid`），**不要破坏 sync 协议**
- 多币种：金额旁币种符号取账本 default_commodity，posting.commodity 同步

**验收**：三 Tab 各记一笔 → 后端 `bean-check` 通过；离线记账→联网同步→数据一致；高级模式改科目后导出路径正确。

## 三、后端梳理结论：**零必须改动**

逐项对照（前端新 UI 需求 → 数据来源 → 结论）：

| # | 前端需求 | 数据来源 | 结论 |
|---|---|---|---|
| 1 | 分类九宫格（支出/收入） | `GET /api/accounts` 过滤 type，icon/color 字段已有（迁移 004） | ✅ 现有 |
| 2 | 账户分组（银行卡/现金/虚拟） | `sub_type` 字段已有（迁移 004） | ✅ 现有 |
| 3 | 成员筛选 chips / 贡献报表 | `GET /api/ledger/members` + 交易 `CreatedByName`（repository 已 JOIN users） | ✅ 现有 |
| 4 | 标签徽章 | `transactions.tags` JSON（迁移 005） | ✅ 现有 |
| 5 | 转账（两笔 posting） | `POST /api/transactions` 支持任意 postings；离线走 sync/push | ✅ 现有 |
| 6 | 日历/排行/双柱/环形聚合 | 前端本地聚合（离线优先架构，全量数据已在端上，现有 reports 页同模式） | ✅ 前端活 |
| 7 | 净资产环比 / 走势 | 本地回放 posting（Beancount 模型含期初 Equity 交易，回放可得） | ✅ 前端活 |
| 8 | 管理员徽章 | `is_admin`（M1 已交付） | ✅ 现有 |
| 9 | 账本切换 | `X-Ledger-Id` + `GET /api/ledgers`（P1-C 已交付） | ✅ 现有 |
| 10 | 登录/注册/改密 | 三个端点均已存在 | ✅ 现有 |
| 11 | 搜索（备注/金额/标签） | 前端本地过滤 | ✅ 前端活 |
| 12 | 备份卡 | M1 三个端点 | ✅ 现有 |

**为什么报表走本地聚合而非后端端点**：产品核心是离线优先——断网也要能看报表；且全量数据已通过 sync 在端上，本地聚合零网络成本；家庭数据量（年数千笔）sembast 毫无压力。后端聚合反而引入"在线才能看报表"的退化。
